# MAP ordering and comparison of the counter routes

First guesslift9c1f and total-domain completion6e871 remain unchanged. If the chosen primary MAP reads its common route first, define the virtual450-bit function output as `(S,T,I41) || J_0 || ... || J_16`,297 route bits followed by153 real-index bits. This is a FIXED PUBLIC PERMUTATION of the fields described in the first. The source actual D bits and literal h words are unchanged; the virtual map returns the same tuple set. A general explicitly specified MAP with the first draft's alternate bit order is equivalent, but the route-first layout removes any ambiguity about a standard slicing convention. Invalid-input completion stays an explicit arbitrary total completion; its actual hardness is not asserted.

Three different routes should not be conflated:

1. Ordinary ITSR of precise H_free with counter guesses: a legal source adapter with q_distinct targets and probability loss L^17=2^544. No accepted-counter oracle is assumed. Hardness of the specified family and adequacy remain open.
2. A bounded nonce/counter rejection adapter might reduce that probability loss by spending many more target queries, but must preserve unconditioned nonce-bottom law and account for any message/context-dependent noncompletion. A nominal qL cost is not automatically valid for arbitrary fixed h: acceptance of a fresh uniform nonce may have mass tau_h(p,M), making a guessed-target acceptance probability tau_h/L. No such resource/error theorem is claimed by this note.
3. Direct CTAC security assumes the canonical-target/arbitrary-counter property expressly and gives a stronger selector-free assumption-parametric statement. It is not the same primitive as ordinary ITSR, and its numerical hardness remains unevaluated.

Only route1 is the new proposed ordinary-primitive lifting lemma here. Route2 is optional future mathematics, not required to validate the existing2^544 inequality. None upgrades old RO bounds or supplies a category/capacity certificate.
