# Selected honest-graph chosen-target challenge: source-first derivation

**PROVED / COMPUTED / OPEN — scope.** This is an explicit finite addressed-RO-relative chosen-target adapter for the type0–4 honest graph event. It is not an identification with a conventional single-key SPR/TCR game, an efficient lazy forest simulator, a Rust refinement, or a forgery construction. No new sibling candidate was read before saving this derivation. The pinned source and previously accepted graph/cache/private-interface results were used. This adapter need not reveal any secret graph advice to the signature adversary.

## 2. Exact addressed chosen-target challenge

**ASSUMED — game definition, openly stronger/different than a standard keyed family.** Before the challenge restriction is sampled, an adapter chooses public S, an address d in D, all key coins, and receives access to an ordinary memoized full256 random oracle Raw_out on the complement of the entire raw header language `S || zero48 || d || {all finite byte strings}`. The missing restriction is not queryable in this phase. It also has private F/J interfaces when the target source game is the accepted joint-private HJ experiment. Those interfaces are independent full256 maps, not extra graph advice given to A. In the real-source variant type5/6 private calls instead use Raw_out with the known key seeds. The adapter commits one finite payload X before any access to the missing restriction.

The challenger then samples a new independent full256 random function H_d on all finite payload byte strings, exposes its ordinary evaluation handle and H_d(X), and continues Raw_out with its existing memo table. A challenge win is an output x != X with `Tr16 H_d(x) = Tr16 H_d(X)`. All full256 responses remain correlated exactly; equality of full256 images is not required. The adapter may evaluate H_d on arbitrary payloads after commitment. The challenge target is chosen, not uniformly sampled, and the commitment may depend on already available independent outside-domain functions.

**PROVED — restriction independence.** In the RO model, every O_d restriction is independent of every other restriction and key coins. Because X_d depends only on strict predecessors, computing X_d using Raw_out before receiving H_d is possible without a circular call. Conditional on every precommit outside response, replacing the absent restriction by an independent random H_d gives exactly the ordinary shared full256 oracle marginal. It is initial independent sampling, not programming over an answered point. Descendants are computed only after H_d is installed. Their dependency on the selected target image is therefore genuine, not fabricated advice.

**OPEN — conventional identification.** This game is an addressed RO-relative chosen-target second-preimage challenge, with outside-oracle access retained across commitment. It is not ordinary single-key SPR/TCR for SHA256 or for a keyed family with a single global public function key. In such a family, predecessor hashes may require the same still-unavailable challenge key; sampling that key early and evaluating predecessors would violate the required pre-key target commitment. For the concrete SHA family the selected restriction cannot simply be swapped for an independent challenger function while preserving all other restrictions. A specific standard-model equivalence or simulator is still required. Naming this game TCR does not supply that equivalence. For a fixed-length challenge one must restrict the extracted event to alternatives with the genuine payload length; the full raw-query G event also includes arbitrary payload lengths and is handled here by the variable-length game explicitly.

## 3. Explicit eager adapter B_G

**PROVED — selection and chronology.** Choose d uniformly from the exact D addresses using rejection sampling on a binary rank; enumerate/unrank the structured types without building the entire address list. Sample S, K, P (or their unused HJ placeholders) before invoking A. Withhold S, pk, the selected d, all graph records and all preparatory work from A. Request Raw_out for the chosen header. Compute the strict predecessor closure of d in topological order using the actual node rules and the selected private-source mode. Commit X_d. Receive H_d and its target response. Define one shared router O_B:

* on any byte word beginning with the exact 86-byte selected header, strip that header and call H_d on the remaining payload;
* on every other byte word, call the same Raw_out handle and its existing memo table.

Do not route by routine name or by the expected payload length. This definition preserves arbitrary raw adversary words, lower128 limbs, aliases and repeats. Finish every remaining designated graph node in topological order through O_B. Previously computed predecessor nodes are reused; the selected node is computed from the supplied H_d target image. Each designated selected-domain query is issued only once in this preparatory phase.

Now invoke A's exact pre-key phase with O_B and no public key/seed disclosed. Preserve the same continuation and total raw-query budget across all phases. If A requests the setup transition, perform the actual top-prepared mathematical setup using the stored graph and the same oracle. Canonical type7 top rows are searched only now; their child roots have already been computed using the genuine graph. Return `(S,root)` and, for the public-cache extension, the exact logical 75,497,456-byte node/counter payload. The seed-bearing fixture is excluded. Resume A with unchanged source signing and snapshot interfaces. The environment serves initiated classical atomic signing requests, retaining a global Seen set and consistent immutable cache handles across all branches. Every complete hash or message query uses O_B, except the explicitly independent F/J private calls in HJ. Existing graph-node reuse is a mathematical memoization of the same source values, not a new externally visible cache interface.

Run the final public verifier, including malformed-input early returns, and compare its returned root to pk.root when defining the source acceptance bit. A returned `Some(root)` alone is not acceptance. Preserve its ordinary ordered classical hash trace. Do not replace verification with a precomputed acceptance oracle. The source never observes which domain is challenged.

**PROVED — extraction.** For the classical raw-access game, retain the ordered raw query words from A's pre-key/post-key phases and final verification, not internal honest preparatory graph calls. Using the stored actual graph, choose the first word in that fixed chronological trace whose address is in D, whose payload differs from its designated X, and whose truncated response equals that address's actual honest output. If its address is d, output its payload to the challenge; otherwise output a failing symbol. This first-witness rule does not depend on d: the complete underlying oracle and adversary transcript have the ordinary source distribution for every d. It is essential not to stop A early only when the selected domain is hit, because such a stop would make witness selection depend on d.

**PROVED — loss.** Couple the complete ordinary oracle, keys and A randomness first, and independently choose uniform d; the challenge adapter realizes this coupling by the restriction-independence argument. Whenever the source event G has a first witness, d equals that witness's address with probability exactly 1/D. Thus

`Pr[challenge win by the first-witness adapter] = Pr[source G] / 39,339,469,515,522,047`.

One may instead extract any selected-domain hit and obtain an inequality at least as large. Multiplying by D gives a valid generic event reduction, but this astronomical target-selection loss is much worse than the direct no-domain-multiplier RO target-hit theorem. The latter is not invalidated or replaced by this fallback.

**PROVED — partiality.** Honest setup/signing grinding is limited in the mathematical adapter to at most L=2^32 distinct counter values. When no acceptable value exists, the source view enters its already defined absorbing nonwinning continuation. This is not a newly visible source abort result or a claim about native Rust overflow/termination. Pre-key logs remain available to the reduction after absorption; a G witness may still be extracted even if the signature game is nonwinning. Consequently the displayed equality is for G on the actual partial trace. For the narrower contribution `Win AND G` the adapter first checks that source bit and extracts only on it, obtaining the same 1/D identity for that conjunction. Failed setup never emits a public key or cache payload. Neither graph precomputation nor extraction conditions the probability space on completion.

## 4. Query, time, storage and private resources

**COMPUTED / PROVED — deterministic classical caps.** Let Q_H count A's complete raw queries over both phases, q count initiated signing calls, L=2^32, and U,D be the counts above. Eager evaluation uses exactly D designated public-domain calls and at most U distinct private starts. In the real-source variant those U starts are additional raw calls; in HJ they are U locally sampled memoized F values and zero public/private primitive-challenge calls. There is no unrelated graph table disclosed to A.

For top-prepared setup the only calls not covered by the precomputed type0–4 graph are at most 2^21 L canonical top type7 evaluations. For a cached sign, full graph values are reusable; a conservative cap on additional calls is 5L+7 (four lower canonical searches plus the FORS filter search; at most five type7 digest rechecks, one inner hash, and one real-source message randomizer). HJ may replace the final randomizer by one J query. A cold sign can instead use 6L+7. This bound deliberately allows rechecking a canonical counter rather than exploiting all repeated oracle calls. Final verification contributes at most3224 complete public calls; at most3217 are types0–4. Setup/signing absorption occurs within these caps. R_total, a safe cap on both oracle handles together, is

`D + U_real + 2^21 L + q*(6L+7) + Q_H + 3224`,

where U_real=U in real-source mode and0 in HJ mode. HJ additionally uses at most U independent F values and q independent message-label J values. A sharper cached-sign cap substitutes5L+7. The selected H_d handle receives at most `1 + Q_H + 3217` calls: one designated target call, all adversarial queries, and final selected-domain verifier calls. All other preparatory designated calls and all honest counter/message calls use Raw_out for nonzero S. Distinct count is never inflated by rebuilding graph nodes. Resource caps refer to primitive full-hash calls, not SHA compression counts, CPU time or quantum cost.

**PROVED — seed-zero qualification.** The exact router works even on S=0 and preserves any message-input overlap with the selected typed header, including variable-length messages. If proving the preceding selected-handle resource cap using disjoint message planes, fix S nonzero; then I and real P-message inputs cannot match the selected prefix because their second16 bytes contain S, while the selected prefix contains zero16 there. E is only52 bytes and cannot have an86-byte prefix. On S=0 charge the complete branch probability1/N once in the final source bound, or use the unrefined unconditional selected-handle cap R_total instead. Do not silently retain the smaller selected-handle cap on S=0. Type5/6 raw private starts remain outside d on every S, by their different address type bytes.

**PROVED — storage and work envelope.** Store every graph record with a22-byte address, a payload of at most512 bytes and full32-byte target response, plus every private start's22-byte address and full32-byte output. This is at most566D+54U raw data bytes, before a balanced-tree dictionary's keys/pointers, the cache payload, canonical counters, transcript and A state. Even before overhead this exceeds practical storage. An explicit implementation has time `t_A + C*((D+U+R_total+q+1)*(599+log2(D+U+R_total+q+2)) + total_message_bytes + total_A_raw_input_bytes)` byte/word operations for some universal C, excluding oracle evaluation cost. Message/query copying contributes their full lengths, not a unit-cost assumption for arbitrarily long strings. Space adds retained transcript bytes, message labels, q signatures and dictionary overhead. The full infinite oracle is not materialized; only finite queried words and the finite actual graph are retained.

**OPEN — useful efficiency.** This finite fallback supplies a well-defined executable mathematical program, but not an efficient reduction at the requested concrete capacity. It computes about39 quadrillion public target domains and19 quadrillion private coordinates before A begins. In an asymptotic family with h growing, this is exponential in h. A lazy alternative would need a separately proved target-payload construction and faithful descendant/setup simulation with honest cost bounds; its feasibility cannot be inferred from memoization or from the no-D-multiplier statistical theorem. No efficient claim is made here.

## 5. Quantum boundary and extraction scope

**PROVED / OPEN.** The existing quantum G theorem uses final classical verifier witnesses, not an observed transcript of quantum oracle queries. For a quantum A, one may formulate the addressed challenge with coherent full256 XOR access and the same classical atomic signing services. The router partitions the raw input by the fixed public header and can forward coherently using one selected-oracle and one outside-oracle invocation per logical raw query with inactive response registers in the uniform-plus state. No measurement or quantum-ever-hit log is permitted. The final classical trace admits the same independent-address witness selection argument for `Win AND G_final`. Its target loss remains1/D. This is a mathematically indicated quantum adapter, not a checked QROM program or an identification with conventional quantum SPR/TCR. The classical ever-query equality in Section3 must not be quoted as a quantum oracle-query extraction theorem.
