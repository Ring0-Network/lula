# Cache canonicality: the universal premise is false

**PROVED — manual deterministic source theorem.** Fix a completing legitimate signature on a message m. At one selected cached WOTS address retain the genuine child, public leaf, subtree root and authentication path. Suppose c0 is its first accepted counter and c1!=c0 is another accepted counter for the same child/address. Modify only that cached counter, leaving the remaining execution genuine. The source emits a different signature on m that verifies against the same public key, without aborting or restoring c0. This theorem requires no random-oracle assumption or inversion.

The source first loads the cached counter and authentic tree data, recomputes its digit vector, and replaces the counter **only if that vector fails acceptance** (`lib.rs635-655`). For an accepted vector x, the signer computes each chain prefix through x_j; verification completes the same addressed chain from x_j to w-1. Their concatenation gives the genuine endpoint for every j (`lib.rs239-276`). The authentic path restores the same layer root and genuine child for the next layer. The serialized BE32 counter words differ even if both accepted vectors coincide. The verifier checks acceptance and final root, not smallest-counter canonicality (`lib.rs714-729`). All statements refer to source SHA256 `ac8e67f05af68dd8e1291c5909847f74103903fb7ffa2c70f500c6ec48f14210`.

**PROVED — positive-support source theorem in the shared raw RO.** For any source-admissible realization of the permitted parameter tuple with injectively represented WOTS row addresses, nonempty operative acceptance predicates, at least two counters and an operational cache-using layer, there is a positive-probability completing source execution meeting the deterministic theorem's hypotheses. No retuning of (a,k,d,h,ell,S) alone makes acceptance-only cached counter selection universally canonical throughout that family.

These are compatible finite constraints on distinct raw inputs, so all source grinds complete. Its row-level two-acceptance factor is p^2>0; the full event also contains the other positive factors. This is a support proof, not a feasible oracle-programming experiment or a fixed-SHA existence assertion. **PROVED — meaning of consistency.** Canonical consistency makes the modified cache inconsistent but the signer does not reject or restore it. Acceptance-valid consistency makes it consistent but does not imply reference byte equality. Thus the original universal abort/recompute-or-equality premise fails under either definition. Empty predicates and removal of all caching make the service premise vacuous; they are not parameter repairs of the retained cached mechanism. The original baseline is in the stated representable RO family. A historical native toy using actual WOTS widths/sums with two height-one layers corroborates the acceptance branch (`../../code-review/RUNS.md:14-18`); it is not a full-baseline security experiment.

**PROVED — security boundaries.** The two signatures are on the same legitimately queried message. This result does not meet the EUF-CMA freshness predicate, establish a forgery advantage, quantify practical failure frequency, or disprove a numerical security target. Honest canonical snapshots, empty-cache reconstruction and the declared atomic interface retain their separately proved exact equality and zero probability/query transfer loss. Arbitrary edited caches require a different validation/trust interface or a separate security analysis. The seed-bearing persistence fixture is still excluded from the admitted public logical cache.
