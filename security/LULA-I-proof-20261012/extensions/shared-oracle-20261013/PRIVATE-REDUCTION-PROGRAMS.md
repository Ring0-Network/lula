## 1. Three exact games and two challenge definitions

**ASSUMED — interface.** Let O be a single full256 random oracle on finite byte strings. Let S,K,P be independent uniform 16-byte strings; fix S nonzero for the following conditional challenge definitions. The partial cryptographic experiment is totalized for this decision-bit adapter as follows: evaluate each signing/setup counter loop for at most L=2^32 distinct counter attempts; if none succeeds, output 0 and enter an absorbing nonwinning result. On the corresponding noncompleting source branch this records no winning completion. It does not manufacture a native Rust abort: a wrapping or nonterminating continuation is modeled as nonwinning, without exposing exhaustion feedback to A. This is the already stated partial cryptographic experiment, not a proof that the Rust `ctr += 1` loop terminates or handles overflow in every build. Classical signing services are atomic; honest consistent caches are opaque; A receives public pk, signatures and raw O replies, never private keys or cache bytes. Let t16 truncate to the first 16 bytes.

**PROVED — exact source words.** For a valid 22-byte type5/6 secret address a, let D(S,a,k)=S||zero48||a||k. The source secret is t16(O(D(S,a,K))). For any message m, M(S,p,m)=p||S||m; the source R is t16(O(M(S,P,m))). The keyed interfaces below return full256 words, with truncation performed by the simulator. Unused lower128 limbs are retained in the challenge's raw O correlation.

**ASSUMED — challenge K.** Input public S and bit b. Sample hidden K uniformly and sample O. Provide Raw(x)=O(x), and Derive(a): if b=0 return O(D(S,a,K)); if b=1 return the memoized independent uniform full256 F(a). The challenger does not disclose K. Its advantage is `|Pr[B_K(Raw,Derive)->1 | b=0]-Pr[... | b=1]|`, without a factor one-half. Raw is the SAME O used by Derive in b=0. This is a joint-access keyed RO construction, not the ordinary independent-oracle PRF experiment.

**ASSUMED — challenge P.** Input public S and bit b. Sample hidden P uniformly and sample O. Provide Raw(x)=O(x), and Randomizer(m): if b=0 return O(M(S,P,m)); if b=1 return the memoized independent uniform full256 J(m). P is not disclosed. Independently sampled F is local simulator state. Define advantage by the same absolute probability difference. Raw is the SAME O used by Randomizer in b=0.

**PROVED — games.** G0 uses both actual private restrictions of O. GK replaces only D by independent F and retains the actual message restriction O(P||S||m). GKP additionally replaces the message restriction by independent J. All other calls, including adversary-chosen message/hash words, use the same ordinary O. The reduction identities below are exact for each fixed nonzero S; there is no guessing of a target leaf and no loss proportional to the secret namespace.

## 2. Explicit B_K

**PROVED — program.** Inputs are S, A, q, and the challenge handles Raw/Derive. Sample P uniformly. Maintain dictionary fcache keyed by the complete type5/6 address. Implement `secret(a)` as: on a cache miss store Derive(a); return t16(fcache[a]). Implement `randomizer(m)` as t16(Raw(P||S||m)); this need not be memoized because Raw is itself a function. Implement every remaining complete-hash source call by Raw on its exact byte word. No simulator code knows, guesses, or reconstructs K. The Ctx placeholder secret fields are never read by an unadapted source `prf` call: all such calls are intercepted by `secret`.

Initialize all challenge handles and the independently sampled P before interaction. The exact phase signature is `pre_key(Raw) -> continuation | abort`. First run A's pre-key phase, forwarding its raw queries to the same Raw handle while withholding S and pk. If A aborts or halts before requesting the setup transition, output the nonwinning bit 0; a forgery is accepted only after the obligatory setup/public-key transition. Otherwise save the returned full A continuation state; no private service is available in the pre-key phase. Then run the configured top-prepared key generation through these adapters, serializing independent work items in a fixed order. If it does not complete, output 0. Give its pk=(S,root) to the saved A continuation and resume it. Forward every subsequent A raw query to the same Raw handle. Q_H counts the total raw queries over both phases, rather than a fresh post-key budget. For at most q initiated message requests, run the reference signature routine with the configured cache-use flag and the same adapters; return only complete signatures, or enter absorbing noncompletion and output 0. Keep a set Seen of requested messages. After A returns `(m*,sigma*)`, compute the exact source verifier through Raw and output `m* not in Seen AND verify(pk,m*,sigma*)`. In particular acceptance compares `verify_root(...)` to pk.root, rather than accepting every returned root. Malformed signatures produce output 0. Final verification calls neither Derive nor the secret randomizer.

**PROVED — identity.** At b=0 this is G0, at b=1 it is GK, including correlations of raw prequeries with private words. Memoizing Derive does not change either distribution. For every bounded event represented by this bit, `|Pr_G0 Win-Pr_GK Win| = Adv_joint-K(B_K)`. Parallel source execution is not a separate probabilistic assumption: disjoint deterministic tasks can be serialized in the model; this does not mechanize allocation, panic or scheduler behavior of Rust.

## 3. Explicit B_P

**PROVED — program.** Inputs are S, A, q, and Raw/Randomizer. Maintain an independent lazy full256 map F on all valid type5/6 addresses, sampling a fresh word only at first access; the original K seed is unused and need not be known. Maintain jcache keyed by exact message bytes. Implement `secret(a)=t16(F[a])`, and `randomizer(m)` as t16(jcache[m]), querying Randomizer(m) only on first access. Initialize the independent F map and challenge handles before A runs. Run precisely the same pre-key/setup/sign/verify/Seen/absorbing-noncompletion program as B_K: forward A's `pre_key(Raw) -> continuation | abort` raw queries with S/pk withheld; on abort or halting before the setup transition output nonwinning bit 0; otherwise save its continuation, perform the obligatory setup, return pk=(S,root) only after completion, then resume it. Use one total Q_H cap across both phases, with all other hash calls forwarded to the same Raw. The simulator never knows P, and never constructs P||S||m itself.

**PROVED — identity.** At b=0 this is GK; at b=1 it is GKP. Thus `|Pr_GK Win-Pr_GKP Win| = Adv_joint-P(B_P)`, and the triangle bound is the sum of these two joint-access advantages. For uniform S, apply the two identities conditional on S!=0, and pay Pr[S=0]=1/N once. Do not manufacture a disjoint-family ideal reconstruction on S=0, where the languages can overlap. Conditional nonzero-S challenges are a proof device, not a modification to production key sampling. An alternative unconditional challenge definition is possible but must retain the overlap; it is not used here.

**PROVED — independence qualification.** In GKP, for a fresh not-yet-queried message label, its J value is uniform independent of the current ideal history before its first query. A repeated message reuses the same value. A signature explicitly exposes its R, so the assertion that R remains independent of *everything A sees after that signature* is false. In G0 the source R has raw-O correlations, paid by the joint-access replacement. Distinct-message truncations may collide; independence of draws does not mean distinctness of outputs.

## 5. Time, storage, and partiality contract

**PROVED — explicit conservative implementation envelope.** Choose a dictionary with a balanced comparison tree over byte strings. Let D be the private distinct-address cap, R the Raw invocation cap, M=sum lengths of all initiated signing messages plus final message, L_A=sum byte lengths of adversarial raw-query words, and t_A its own runtime. Maximum honest fixed addressed input length is 598 bytes (86-byte typed prefix plus 32*16 WOTS compressor), maximum signature size is 5,720, and private addressed input length is 102. Dictionary word comparisons cost at most input length plus one; full256 outputs cost a constant. A word-RAM implementation of B_K/B_P uses at most `t_A + C*( (R+D+q+1)*(599+41+log2(R+D+q+2)) + M*(1+log2(q+2)) + L_A )` word operations for one universal constant C, excluding cost of challenger oracle evaluations. This conservative envelope includes complete tree construction, digest digit decoding, output copying and membership checks; exact wall-clock seconds are neither measured nor claimed. Opaque snapshot handles need only bookkeeping proportional to handles created by A; those costs belong to t_A plus copied handle length. A service may alternatively recompute rather than retain memoized public trees, trading space for time but preserving challenge counts.

**PROVED — storage cap.** Excluding A and challenger storage, an explicit non-streaming simulator stores at most O(32D + M + q*5720 + 75497456 + 64*2^22 + 64*17*1023) bytes for private tables, messages, retained transcript, configured cache and live tree/intermediate vectors, plus dictionary pointers/keys (22D address bytes and message bytes). The deliberately generous top-vector allowance covers temporary keygen items as well as tree nodes. Full public hash memoization is optional and adds O(32R + L_A + 599R + M) bytes if chosen. The full infinite RO is not precomputed. Honest setup has billions of calls, so feasible concrete speed is not claimed, but the reduction is finite and efficient relative to the explicit source service cost; it does not enumerate the full 19-quadrillion-address namespace or the complete secret forest.

## 6. Connection to the reviewed private hops

**PROVED — loss interpretation.** The exact adapter identities allow the already reviewed information-theoretic source couplings to bound these particular ROM-relative distinguishers. For nonzero S, the K-only sequential hop has a sufficient classical raw-key-guess bound Q_H/N: all honest nonprivate calls and all REAL P calls are structurally outside D. In the ideal K game the hidden K is unused. For the P-only hop, a sufficient bound is `(Q_H+2q+2)/N`: a raw query nominates at most one P; each initiated sign nominates at most one inner R and one outer U-prefix; final verification contributes two. These sequential bounds sum to `(2Q_H+2q+2)/N`, before the single S=0 charge. They are valid but looser than the reviewed joint coupling's `(Q_H+2q+2)/N`. The sharp joint bound should therefore remain the numerical theorem's private term. The raw caps in Section 4 are simulator resources; honest structurally excluded calls are not hidden-key guesses.

**OPEN — conventional PRF certification.** If the original Point2.1 insists on a conventional PRF with no common raw oracle, that exact source obligation remains unclosed. Its smallest missing lemma is a simulator/reduction showing equivalence to that conventional experiment while preserving all raw correlations, or a source change with a genuinely independent cryptographic primitive (outside scope). The ROM-relative construction is explicitly identified and does not establish fixed SHA-256 security. Quantum sequential adapter identities may be defined with coherent Raw and classical private interfaces, but this document does not mechanize or replace the accepted joint finite-QROM proof.
