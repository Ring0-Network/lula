# Query-budget failure bounds and security categories

**CITED — official category definition.** NIST's [evaluation criteria, section4.A.5](https://csrc.nist.gov/Projects/Post-Quantum-Cryptography/Post-Quantum-Cryptography-Standardization/Evaluation-Criteria/Security-%28Evaluation-Criteria%29) define category1 by attack resources compared with AES-128 key search. They discuss several resource metrics, including circuit size and depth. This is not a requirement that success remain at most2^-64 after2^64 idealized oracle calls. Section4.A.4 separately describes EUF-CMA with classical signing queries; a signing-query capacity is not the same quantity as an adversary's hash-search budget. The primary page was read on2026-10-13; it reports an August2026 update.

**PROVED — elementary distinction.** In an ideal unique-key search space of N uniform keys, testing Q distinct candidates has success min(1,Q/N). At Q=N the success is one, despite the search requiring N candidate tests. A demand that success be at most1/N at that same budget cannot express the usual search-work benchmark. This toy identity is not a theorem about actual AES implementation cost.

**PROVED — distinct statistical parameter.** A bound epsilon(q,Q)<=2^-b describes a specific small winning probability under specified q/Q budgets. A work-factor or resource category instead requires a stated success criterion and a resource comparison. Replacing one with the other without those definitions is invalid. In particular, -log2 epsilon at a fixed Q is not automatically the number of security bits of a construction.
