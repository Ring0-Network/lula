# Why second-preimage resistance alone does not imply one-time WOTS security

**PROVED — abstract separation, not a LULA I attack.** The goal requests a one-time WOTS+C reduction under second-preimage resistance alone. That implication is false for a general fixed-width chain-function family with same-tweak second-preimage resistance. Fix every position/tweak function to the identity on the block space. Identity is injective: at a fixed tweak no different input has the same image, so that second-preimage advantage is zero. Its predecessor is nevertheless publicly computable. This does not claim cross-tweak binding or second-preimage resistance of a complete variable-length hash with the tweak inside its raw input; stronger assumptions can exclude this countermodel.

**PROVED — chain exposure.** For any initial chain value z and any position p, identity iterated p times returns z. A signature therefore exposes every chain's initial value. The same block vector passes chain completion for every admissible digest vector, irrespective of its digits. Its ordered endpoints and compressed public key remain unchanged. No second preimage or chain merger is used.

**COMPUTED — fixed-parameter digit control.** For the lower-layer parameters w=16, ell=32, S=240, the vectors with sixteen leading 15s followed by sixteen zeros, and sixteen leading zeros followed by sixteen 15s, are distinct accepted sum vectors. Both total 240. Neither is coordinate-wise above the other. Their chain blocks and completed endpoints are identical in the countermodel. Thus the antichain argument prevents forward movement on genuine one-way chains; injectivity alone does not supply that one-way property. An unrestricted digest oracle can supply two fresh labels with those respective accepted vectors. This is a countermodel to an assumption implication, not a statement about SHA-256.

**PROVED — checked algebraic components.** `root-formal/SPRSeparation.lean` has four checked declarations: identity injectivity, identity iteration, equality of chain-block vectors for arbitrary digit vectors, and a public inverse. The local Lean run exits zero; `root-formal/SPRSeparation-check.json` records source SHA-256 `bec31567ae07abbdf8ae868b2d2f804fe469dce276d938bf6fdd8a24e1a425da`. Three declarations use no axioms; vector equality uses only propext and Quot.sound. These are algebraic facts, not a machine-checked EUF-CMA game or a source refinement.

**OPEN — replacement obligation.** A generic primitive theorem must add an appropriate preimage/one-way assumption for the genuine-predecessor case and state its exact challenge embedding and loss. The separate reviewed shared-RO source theorem handles that case through its hidden-input event. This counterexample neither refutes that RO theorem nor changes the actual source primitive, parameters or implementation.
